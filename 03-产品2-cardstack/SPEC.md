# SPEC · CardStack

纯前端知识卡片生成器的需求、MVP 范围与技术决策。

## 1. 需求

### 1.1 用户与场景
- **用户**：公众号 / 小红书 / 知识星球的内容作者，不懂设计但需要高频产出「观点卡片」。
- **场景**：写完一段观点 → 想配一张好看的卡片发出去 → 现有工具贵 / 乱 / 要上传。
- **痛点**：审美门槛 + 工具成本 + 隐私顾虑。

### 1.2 用户故事
- 作为作者，我要**输入标题和几个要点**，立刻看到一张排版精美的卡片。
- 作为作者，我要**一键切换几套风格**，不用自己调颜色字体。
- 作为作者，我要**选竖图或方图**，分别适配公众号和小红书。
- 作为作者，我要**导出高清 PNG**，发出去不糊。
- 作为作者，我**不希望我的文字被上传**到任何服务器。

### 1.3 验收标准
- 打开 `index.html` 即可用，无需安装/构建/登录。
- 编辑任意字段，预览实时更新（< 100ms 感知）。
- 4 套模板可一键切换，风格明显不同且都「不廉价」。
- 2 种尺寸可切换，卡片在两种比例下都排版精致。
- 点击导出，真实下载一张 2x 清晰度的 PNG，内容与预览一致。
- 用户输入特殊字符（`<`、`&`、引号）不破坏排版、无脚本注入。

## 2. MVP 范围

### In scope（做）
- 编辑区：kicker / 标题 / 副标题 / 要点(增删，1–8 条) / 署名。
- 实时预览。
- 4 套模板：暗色科技、暖色编辑、极简留白、知识卡渐变。
- 2 种尺寸：1080×1440、1080×1080。
- 一键导出 PNG（pixelRatio = 2）。
- 输入转义 + 基本错误处理 + Toast 反馈。
- 响应式（窄屏上下布局）。

### Out of scope（明确不做，留给后续路线）
- 账号 / 云端 / 协作。
- 模板市场 / 社区投稿。
- 批量长文切卡。
- 自定义字体上传、品牌色拾取器。
- 后端、数据库、付费墙（变现在路线图，MVP 先验证「人们爱用」）。

> 对齐刘小排「小而锋利、一两天做完、先让一群人爱上」——MVP 只验证核心体验。

## 3. 技术决策

### 3.1 纯前端、无构建
- **决策**：原生 HTML + CSS + ES2015 JS，CDN 引字体与导出库，无 npm/webpack/打包。
- **理由**：降到「双击即用」的最低门槛；契合「一两天做完」；零部署成本（任意静态托管/直接发文件）。

### 3.2 数据与渲染分离
- **决策**：模板是 `templates.js` 里的纯数据（CSS 变量集合 + 尺寸），渲染逻辑统一在 `app.js`。
- **理由**：新增模板 = push 一个对象，「换皮不换骨」。可维护、可扩展，符合「模板库是护城河」的产品判断。

### 3.3 不可变 state + 单一渲染入口
- **决策**：`state` 用 `Object.freeze`，所有变更走 `setState({...patch})` 返回新对象后重渲染；要点数组用 `map/filter` 生成新数组，绝不就地 mutate。
- **理由**：状态可预测、易调试，符合团队编码规范（immutability）。
- **细节**：要点输入框「实时改 state 但不重建编辑器 DOM」，避免输入时光标跳动；只有增删（结构变化）才重建编辑器列表。

### 3.4 导出方案：克隆节点 + html-to-image
- **决策**：导出时**克隆** `.card` 到离屏容器，清掉预览用的 `transform: scale()`，按尺寸预设锁死真实像素，再用 `html-to-image.toPng(pixelRatio=2)` 渲染。
- **理由**：
  - 预览区为适配屏幕用了 `scale()`，直接截图会把缩放截进去 → 糊或尺寸错。克隆出 1:1 干净节点最清晰。
  - `html-to-image` 纯前端、无后端、支持 webfont 内联，满足「不上传」硬约束。
- **备选与权衡**：
  - `dom-to-image`：旧、维护少 → 弃。
  - `canvas` 手写绘制：可控但要自己处理换行/字体/排版，成本高、不划算 → MVP 弃。
  - 服务端 Puppeteer 截图：最稳但需要后端，违反「本地/隐私/零部署」→ 弃。

### 3.5 字体
- **决策**：Inter（拉丁无衬线）+ Noto Serif SC / Noto Sans SC（中文衬线/黑体），Google Fonts CDN。
- **理由**：中文衬线带来「编辑/杂志感」的高级气质；Inter 干净克制。导出前等两帧确保 webfont 应用，避免导出图回退系统字体。

### 3.6 视觉「高级感」的具体手段（反 AI 廉价感）
- 严格字号层级：kicker 22 / 标题 76 / 要点 36 / 署名 24（竖图），方图整体降一档。
- 充足留白：内边距 96/88，要点间细分隔线而非粗描边。
- 单一强调色 + 克制阴影（长投影 `0 24px 60px -20px`），不堆叠多色渐变。
- 圆点 + 柔光环代替廉价 emoji/icon。

### 3.7 安全
- 所有用户输入经 `escapeHtml` 再插入 DOM；换行经转义后才 `nl2br`。
- 无密钥、无外发用户数据、无 `eval`。
- 依赖项固定版本（`html-to-image@1.11.11`）避免 CDN 漂移。

### 3.8 离线化路径（后续）
- 把 CDN 的 `html-to-image.js` 与字体下载到本地，改本地引用即可完全离线 / 打包成 PWA。

## 4. 风险与缓解
| 风险 | 缓解 |
|---|---|
| 首次导出需联网拉 CDN | README 标注；提供本地化引用方案 |
| webfont 未加载就导出 → 字体回退 | 导出前 `requestAnimationFrame` 等两帧 |
| 用户超长标题溢出 | 卡片用绝对定位 + 固定尺寸，超长由作者自行精简（卡片本就追求克制）；字段有 maxlength |
| `file://` 下个别浏览器字体/CORS 限制 | README 推荐起本地静态服务器 |
